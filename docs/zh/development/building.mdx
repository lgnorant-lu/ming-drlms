## 概述

DRLMS 包含 Python 客户端和 C 服务器两个主要组件。本指南介绍如何从源码构建。

---

## Python 客户端

### 前置条件

- Python 3.9+
- pip 或 uv

### 平台隔离原则

<Warning>
Windows 与 WSL 不能共用同一个 venv（ABI、路径、脚本均不兼容）。
</Warning>

建议使用两个并行虚拟环境：
- Windows: `.venv.win`
- WSL/Linux: `.venv.wsl`

### 开发安装

<Tabs>
  <Tab title="Windows">
    ```powershell
    git clone https://github.com/lgnorant-lu/ming-drlms.git
    cd ming-drlms

    # 创建 Windows 专用虚拟环境
    uv venv .venv.win
    .\.venv.win\Scripts\Activate.ps1

    # 安装依赖
    uv pip install -e ".[dev,relay]"

    # 验证安装
    uv pip check
    ```
  </Tab>
  <Tab title="WSL/Linux">
    ```bash
    git clone https://github.com/lgnorant-lu/ming-drlms.git
    cd ming-drlms

    # 创建 WSL 专用虚拟环境
    uv venv .venv.wsl
    source .venv.wsl/bin/activate

    # 安装依赖
    uv pip install -e ".[dev,relay]"

    # 验证安装
    uv pip check
    ```
  </Tab>
</Tabs>

### 构建 wheel

```bash
uv pip install build
python -m build
```

输出：
```
dist/
├── ming_drlms-0.3.0-py3-none-any.whl
└── ming_drlms-0.3.0.tar.gz
```

## C 服务器

### 前置条件

- CMake 3.18+
- C 编译器（GCC、Clang 或 MSVC）
- vcpkg（依赖管理）

### 安装 vcpkg

```bash
# Linux/macOS
git clone https://github.com/Microsoft/vcpkg.git ~/vcpkg
cd ~/vcpkg
./bootstrap-vcpkg.sh
export VCPKG_ROOT=~/vcpkg

# Windows
git clone https://github.com/Microsoft/vcpkg.git D:\vcpkg
cd D:\vcpkg
.\bootstrap-vcpkg.bat
set VCPKG_ROOT=D:\vcpkg
```

### 安装依赖

#### 方式一：Manifest 模式（推荐）

项目根目录已包含 `vcpkg.json`，CMake 会自动安装依赖：

```json
{
  "name": "ming-drlms",
  "version-string": "1.0.0",
  "dependencies": [
    { "name": "openssl", "features": ["tools"] },
    "sqlite3",
    "argon2",
    "protobuf-c"
  ]
}
```

配置时指定 toolchain 即可：

```bash
cmake -S . -B build -DCMAKE_TOOLCHAIN_FILE=$VCPKG_ROOT/scripts/buildsystems/vcpkg.cmake
```

#### 方式二：传统模式

手动安装依赖：

```bash
vcpkg install sqlite3 openssl argon2 protobuf-c --triplet x64-windows  # Windows
vcpkg install sqlite3 openssl argon2 protobuf-c                        # Linux
```

<Note>
使用 `protobuf-c` 而非 `protobuf`（C 语言版本）。
</Note>

### OpenSSL 配置（CFFI 构建必需）

Python CFFI 构建 Signal Bridge 时需要 OpenSSL 头文件：

<Tabs>
  <Tab title="Windows">
    ```powershell
    # vcpkg 安装后设置
    $env:OPENSSL_ROOT_DIR = "$PWD\vcpkg_installed\x64-windows"
    
    # 或全局 vcpkg
    $env:OPENSSL_ROOT_DIR = "C:\vcpkg\installed\x64-windows"
    
    # 验证
    Test-Path "$env:OPENSSL_ROOT_DIR\include\openssl\evp.h"
    ```
  </Tab>
  <Tab title="Linux/WSL">
    ```bash
    # vcpkg 安装后设置
    export OPENSSL_ROOT_DIR=$PWD/vcpkg_installed/x64-linux
    
    # 或系统安装
    export OPENSSL_ROOT_DIR=/usr
    
    # 验证
    ls $OPENSSL_ROOT_DIR/include/openssl/evp.h
    ```
  </Tab>
</Tabs>

<Warning>
若 `OPENSSL_ROOT_DIR` 未正确设置，CFFI 构建将失败并报错 `openssl/evp.h: No such file`。
</Warning>

### 构建

<Tabs>
  <Tab title="Linux/macOS">
    ```bash
    mkdir build && cd build
    cmake .. -DCMAKE_TOOLCHAIN_FILE=$VCPKG_ROOT/scripts/buildsystems/vcpkg.cmake
    make -j$(nproc)
    ```
  </Tab>
  <Tab title="Windows (VS 2022)">
    ```powershell
    mkdir build
    cd build
    cmake .. -G "Visual Studio 17 2022" -DCMAKE_TOOLCHAIN_FILE=$env:VCPKG_ROOT/scripts/buildsystems/vcpkg.cmake
    cmake --build . --config Release
    ```
  </Tab>
  <Tab title="Windows (VS 2026 + Ninja)">
    在 **x64 Native Tools Command Prompt for VS 2026** 中执行：

    ```cmd
    cd path\to\DRLMS
    rmdir /S /Q build_win_ninja_x64 2>nul
    mkdir build_win_ninja_x64
    cd build_win_ninja_x64

    cmake -G "Ninja" ^
      -DCMAKE_BUILD_TYPE=RelWithDebInfo ^
      -DOPENSSL_ROOT_DIR=%CD%\..\vcpkg_installed\x64-windows ^
      -DPROTOBUF_C_USE_PREGENSETS=OFF ^
      ..
    cmake --build . --target log_collector_server drlms_signal_bridge
    ```

    <Note>
    VS 2026 需使用 Ninja 生成器，直接使用 VS 生成器可能无法正确识别。
    </Note>
  </Tab>
</Tabs>

### 输出

<Tabs>
  <Tab title="Linux/macOS">
    ```
    build/
    ├── log_collector_server         # 主服务器
    ├── libipc.so / libipc.a         # IPC 共享/静态库
    └── libdrlms_signal_bridge.so    # Signal Protocol + XEdDSA 桥接库
    ```
  </Tab>
  <Tab title="Windows">
    ```
    build/                           # VS 2022 输出
    build_win_ninja_x64/             # VS 2026 + Ninja 输出
    ├── log_collector_server.exe     # 主服务器
    ├── ipc.dll / ipc.lib            # IPC 动态/静态库
    └── drlms_signal_bridge.dll      # Signal Protocol + XEdDSA 桥接库
    ```
  </Tab>
</Tabs>

## Signal Bridge 库（含 XEdDSA）

### 架构说明

XEdDSA 签名功能集成在 `drlms_signal_bridge` 共享库中：
- 源码：`src/ming_drlms/core/drlms_xeddsa.c`
- 与 Signal Protocol 库一起编译
- 通过 CFFI 暴露给 Python

### Python 绑定

Signal Bridge 库通过 CFFI 绑定到 Python：

<Tabs>
  <Tab title="Linux/WSL">
    ```bash
    # 设置库路径（指向 cmake 构建目录）
    export DRLMS_SIGNAL_PREFIX=/path/to/build
    
    # 验证签名功能
    python -c "from ming_drlms.core.pysignal.signature import verify_bytes; print('OK')"
    
    # 验证 XEdDSA 自检
    ming-drlms xeddsa-selftest --user myuser
    ```
  </Tab>
  <Tab title="Windows">
    ```powershell
    # 设置库路径（指向 cmake 构建目录）
    $env:DRLMS_SIGNAL_PREFIX = "C:\path\to\build"
    
    # 验证签名功能
    python -c "from ming_drlms.core.pysignal.signature import verify_bytes; print('OK')"
    
    # 验证 XEdDSA 自检
    ming-drlms xeddsa-selftest --user myuser
    ```
  </Tab>
</Tabs>

## CMake 选项

| 选项 | 默认值 | 说明 |
|------|--------|------|
| `ENABLE_TESTS` | ON | 构建 C 测试二进制 |
| `BUILD_SERVER` | ON | 构建服务器及其依赖 |
| `ENABLE_COVERAGE` | OFF | 启用覆盖率插桩 |

使用：

```bash
cmake .. -DENABLE_TESTS=ON -DENABLE_COVERAGE=ON
```

## 发布流程

### 版本号

遵循语义化版本：`MAJOR.MINOR.PATCH`

### 发布步骤

1. 更新版本号
   ```bash
   # pyproject.toml
   version = "0.3.1"
   ```

2. 更新 CHANGELOG

3. 创建标签
   ```bash
   git tag -a v0.3.1 -m "Release v0.3.1"
   git push origin v0.3.1
   ```

4. 构建并上传
   ```bash
   python -m build
   twine upload dist/*
   ```

## 故障排查

### 常见问题速查表

| 问题 | 可能原因 | 解决方案 |
|------|----------|----------|
| CMake 找不到编译器 | 未在 VS Native Tools 命令行中运行 | 打开 `x64 Native Tools Command Prompt` |
| 链接阶段缺少 `ws2_32.lib` | 未链接 Winsock | CMakeLists 添加 `ws2_32` |
| Argon2 构建失败 | vcpkg 版本过旧 | `git pull && bootstrap-vcpkg.bat` |
| OpenSSL 路径冲突 | 多个 OpenSSL 版本 | 清理 build 目录，确保 PATH 正确 |
| CFFI `openssl/evp.h` 缺失 | `OPENSSL_ROOT_DIR` 未设置 | 设置环境变量指向 OpenSSL 目录 |
| vcpkg manifest 失败 | `vcpkg.json` 格式错误 | 检查 JSON 格式，更新 vcpkg |
| VS 2026 MSBuild 失败 | 生成器兼容性问题 | 使用 Ninja：`-G "Ninja"` |
| `signal-protocol-c.lib` 找不到 | triplet 不匹配 | 确认 `x64-windows` triplet |

### CMake 找不到依赖

确保 vcpkg 工具链正确配置：

<Tabs>
  <Tab title="Linux/WSL">
    ```bash
    cmake .. -DCMAKE_TOOLCHAIN_FILE=$VCPKG_ROOT/scripts/buildsystems/vcpkg.cmake
    ```
  </Tab>
  <Tab title="Windows">
    ```powershell
    cmake .. -DCMAKE_TOOLCHAIN_FILE="$env:VCPKG_ROOT\scripts\buildsystems\vcpkg.cmake"
    ```
  </Tab>
</Tabs>

### 链接错误

检查库路径：

<Tabs>
  <Tab title="Linux/WSL">
    ```bash
    export LD_LIBRARY_PATH=/path/to/libs:$LD_LIBRARY_PATH
    ```
  </Tab>
  <Tab title="Windows">
    ```powershell
    # Windows 不使用 LD_LIBRARY_PATH，确保 DLL 在 PATH 中
    $env:PATH = "C:\path\to\libs;$env:PATH"
    ```
  </Tab>
</Tabs>

### Python 扩展加载失败

检查 CFFI 绑定：

```bash
python -c "from ming_drlms.core.pysignal._ffi import ffi, lib; print(lib)"
```

### Windows 特有问题

#### VS 2026 构建失败

VS 2026 的 MSBuild 生成器可能存在兼容性问题，推荐使用 Ninja：

```cmd
:: 在 x64 Native Tools Command Prompt for VS 2026 中
cmake -G "Ninja" -DCMAKE_BUILD_TYPE=RelWithDebInfo ..
```

#### 多工具链冲突

<Warning>
同一终端会话内不要混用 MSVC 与 MinGW-w64 工具链。本项目统一使用 MSVC。
</Warning>

## 日志配置

### 环境变量

| 变量 | 默认值 | 说明 |
|------|--------|------|
| `DRLMS_LOG_LEVEL` | `INFO` | 日志级别 (DEBUG/INFO/WARN/ERROR) |
| `DRLMS_LOG_DIR` | `~/.drlms/logs` | 日志目录 |
| `DRLMS_LOG_CONSOLE` | `1` | 是否输出到控制台 |
| `DRLMS_LOG_JSON` | `0` | 是否输出 JSON 格式 |

### 日志文件

| 文件 | 说明 |
|------|------|
| `drlms.log` | Python 主日志 |
| `drlms_error.log` | 错误专用日志 |
| `drlms_c.log` | C 端日志 |
