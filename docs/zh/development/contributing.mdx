## 开发环境

### 克隆仓库

```bash
git clone https://github.com/lgnorant-lu/ming-drlms.git
cd ming-drlms
```

### 安装依赖

<Tabs>
  <Tab title="Linux/WSL">
    ```bash
    # 创建虚拟环境
    python -m venv .venv
    source .venv/bin/activate
    
    # 安装开发依赖
    pip install -e ".[dev]"
    ```
  </Tab>
  <Tab title="Windows">
    ```powershell
    # 创建虚拟环境
    python -m venv .venv
    .venv\Scripts\Activate.ps1
    
    # 安装开发依赖
    pip install -e ".[dev]"
    ```
  </Tab>
</Tabs>

### 安装预提交钩子

```bash
make hook-install
```

<Note>
项目使用自定义 Git 钩子（`.githooks/pre-commit`），不使用 pre-commit 框架。
钩子会自动运行 ruff format 和 ruff check。
</Note>

## 代码规范

### Python 风格

- 遵循 PEP 8
- 使用 ruff format 格式化
- 使用 ruff check 检查代码问题
- 类型注解（Python 3.9+ 语法）

```python
from __future__ import annotations

def process_message(content: str, sender: str | None = None) -> dict[str, Any]:
    """处理消息内容。
    
    Args:
        content: 消息内容
        sender: 发送者（可选）
        
    Returns:
        处理结果字典
    """
    ...
```

### C 风格

- K&R 风格缩进
- 4 空格缩进
- 函数前注释说明

```c
/**
 * 处理客户端连接
 * @param conn 连接结构体指针
 * @return 0 成功，-1 失败
 */
int handle_connection(connection_t* conn) {
    ...
}
```

## 提交规范

### Conventional Commit 消息格式

```
<type>(<scope>): <subject>

<body>

<footer>
```

### Type 类型

| Type | 说明 |
|------|------|
| `feat` | 新功能 |
| `fix` | 修复 Bug |
| `docs` | 文档更新 |
| `style` | 代码格式（不影响逻辑） |
| `refactor` | 重构 |
| `test` | 测试相关 |
| `chore` | 构建/工具相关 |

### 示例

```
feat(relay): add merkle tree consistency check

- Implement incremental merkle tree building
- Add proof generation and verification
- Support diff computation between trees

Closes #123
```

## Pull Request 流程

### 1. Fork 仓库

在 GitHub 上 Fork 项目到你的账号。

### 2. 创建分支

```bash
git checkout -b feature/your-feature-name
```

分支命名：
- `feature/xxx` - 新功能
- `fix/xxx` - Bug 修复
- `docs/xxx` - 文档更新

### 3. 开发与测试

```bash
# 运行测试
pytest

# 运行 lint
ruff check src/

# 格式化
ruff format src/ tests/
```

### 4. 提交代码

```bash
git add .
git commit -m "feat(scope): description"
git push origin feature/your-feature-name
```

### 5. 创建 PR

在 GitHub 上创建 Pull Request，填写：
- 标题（遵循 commit 格式）
- 描述（说明改动内容）
- 关联 Issue（如有）

---

## 测试要求

### 测试覆盖

- 新功能必须有对应测试
- Bug 修复需要回归测试
- 目标覆盖率：80%+

### 测试命令

```bash
# 运行所有测试
pytest

# 带覆盖率
pytest --cov=src/ming_drlms

# 运行特定测试
pytest tests/python/test_relay_merkle.py -v
```

## 文档要求

### 代码文档

- 公共 API 必须有 docstring
- 复杂逻辑添加行内注释
- 更新 CHANGELOG

### 用户文档

新功能需要更新：
- README（如需要）
- 相关 docs/ 文档
- CLI --help 文本

---

## Issue 报告

### Bug 报告

使用 Bug Report 模板，包含：
- 环境信息（OS、Python 版本）
- 复现步骤
- 期望行为
- 实际行为
- 日志/截图

### 功能请求

使用 Feature Request 模板，包含：
- 使用场景
- 期望功能
- 可能的实现方案

---

## 代码审查

### 审查要点

- 代码逻辑正确性
- 测试覆盖
- 文档完整性
- 安全考虑
- 性能影响

### 响应时间

- 维护者会在 1-3 个工作日内响应
- 复杂 PR 可能需要更长时间
