## 概述

MP2 模式是 DRLMS 的传统运行模式，使用 C 语言实现的 `log_collector_server` 作为中心服务器。适合需要集中管理的场景。

---

## 启用 MP2 模式

### 环境变量配置

<Tabs>
  <Tab title="Linux/WSL">
    ```bash
    export DRLMS_BACKEND_MODE=mp2
    export DRLMS_MP2_HOST=127.0.0.1
    export DRLMS_MP2_PORT=15035
    ```
  </Tab>
  <Tab title="Windows">
    ```powershell
    $env:DRLMS_BACKEND_MODE = "mp2"
    $env:DRLMS_MP2_HOST = "127.0.0.1"
    $env:DRLMS_MP2_PORT = "15035"
    ```
  </Tab>
</Tabs>

### 配置文件

在 `config.toml` 中：

```toml
[backend]
mode = "mp2"

[mp2]
host = "127.0.0.1"
port = 15035
tls = false
```

## 跨平台连接配置

### WSL/Linux 连接 Windows 服务器

当 MP2 服务器运行在 Windows，而客户端在 WSL 或 Linux 时，需要额外配置。

#### 1. 网络配置

**获取 Windows 主机 IP**（在 WSL 中执行）:

<Tabs>
  <Tab title="WSL 2">
    ```bash
    # 查看 WSL 网关（即 Windows 主机 IP）
    grep nameserver /etc/resolv.conf | awk '{print $2}'
    # 输出示例: 10.255.255.254
    ```
  </Tab>
  <Tab title="物理 Linux 机器">
    ```bash
    # 查看 Windows 服务器的实际 IP
    # 例如通过 ping 或网络管理工具获取
    # 示例: 192.168.1.100
    ```
  </Tab>
</Tabs>

**配置客户端连接此 IP**:

<Tabs>
  <Tab title="环境变量（临时）">
    ```bash
    export DRLMS_MP2_HOST=10.255.255.254  # 替换为实际 IP
    export DRLMS_MP2_PORT=15035
    ```
  </Tab>
  <Tab title="配置文件（永久）">
    编辑 `~/.drlms/config.toml`:
   ```toml
    [backend.mp2]
    host = "10.255.255.254"  # 替换为实际 IP
    port = 15035
    tls = false
    ```
  </Tab>
</Tabs>

#### 2. Windows 防火墙配置

**问题**: 即使服务器监听 `0.0.0.0:15035`，Windows 防火墙默认阻止外部连接，导致 WSL 连接被拒绝。

**解决**: 添加入站规则允许 15035 端口。

**步骤** (Windows PowerShell 管理员):

1. 打开管理员 PowerShell:
   - 按 `Win + X`
   - 选择 "Windows PowerShell (管理员)" 或 "终端 (管理员)"

2. 执行防火墙规则添加命令:
   ```powershell
   New-NetFirewallRule -DisplayName "DRLMS MP2 Server (WSL Access)" `
       -Direction Inbound `
       -Action Allow `
       -Protocol TCP `
       -LocalPort 15035 `
       -Profile Any
   ```

3. 验证规则已创建:
   ```powershell
   Get-NetFirewallRule -DisplayName "DRLMS MP2 Server (WSL Access)"
   ```

**预期输出**:
```
DisplayName : DRLMS MP2 Server (WSL Access)
Enabled     : True
Direction   : Inbound
Action      : Allow
```

#### 3. 测试连接

**在 WSL/Linux 中测试端口连通性**:

<Tabs>
  <Tab title="使用 nc (推荐)">
    ```bash
    nc -zv <Windows_IP> 15035
    # 成功输出: Connection to <IP> 15035 port [tcp/*] succeeded!
    ```
  </Tab>
  <Tab title="使用 telnet">
    ```bash
    telnet <Windows_IP>15035
    # 成功: 显示空白屏幕（按 Ctrl+] 然后 quit 退出）
    ```
  </Tab>
  <Tab title="使用 bash">
    ```bash
    timeout 3 bash -c '</dev/tcp/<Windows_IP>/15035' && \
        echo "Port is open" || echo "Port is closed"
    ```
  </Tab>
</Tabs>

#### 4. 创建用户身份

WSL 用户首次连接前需要创建本地身份：

```bash
# 创建身份（Relay 模式兼容层）
ming-drlms identity create -u <用户名>

# 查看身份
ming-drlms identity show
```

<Note>
MP2 模式使用 Relay 的本地身份系统。首次连接时，客户端会自动向服务器注册用户。
</Note>

#### 5. 常见错误排查

| 错误信息 | 原因 | 解决方案 |
|---------|------|---------|
| `Connection refused` | 防火墙阻止 | 执行上述防火墙规则添加（步骤 2） |
| `No route to host` | WSL 网络配置异常 | 重启 WSL: `wsl --shutdown` (Windows端) |
| `Timeout` | 服务器未运行 | 启动服务器: `ming-drlms server up` |
| `server did not return tokens` | 用户身份未创建 | 执行步骤 4 创建身份 |

## 启动服务器

### 快速启动

```bash
ming-drlms server up --port 15035 -d server_files
```

### 启动选项

| 选项 | 简写 | 默认值 | 说明 |
|------|------|--------|------|
| `--port` | `-p` | `15035` | 监听端口 |
| `--data-dir` | `-d` | `server_files` | 数据目录 |
| `--strict/--no-strict` | `-S` | `true` | 严格认证模式 |
| `--max-conn` | `-m` | `128` | 最大连接数 |
| `--config` | `-c` | - | 配置 yaml 文件路径 |
| `--verbose` | `-v` | `false` | 显示服务器输出 |

### 使用演示模式

```bash
ming-drlms demo quickstart
```

此命令会自动启动服务器并创建测试用户。

## 用户认证

### 登录

```bash
ming-drlms login -u <用户名> -H <主机> -p <端口>
```

示例：

```bash
ming-drlms login -u myuser -H 127.0.0.1 -p 15035
```

### 认证流程

1. 客户端发送 Challenge 请求
2. 服务器返回随机 nonce
3. 客户端计算 `Argon2id(password + nonce)`
4. 服务器验证并返回 JWT AccessToken
5. 后续请求携带 JWT

### 用户管理

用户存储在 `server_files/users.txt`：

```
# 格式: username:password_hash:role
myuser:$argon2id$v=19$m=65536,t=2,p=1$...:user
peer:$argon2id$v=19$m=65536,t=2,p=1$...:admin
```

## 房间管理

### 创建房间

```bash
ming-drlms room create -r <房间名>
```

### 订阅房间

```bash
ming-drlms room sub -r <房间名> -u <用户名> -H <主机> -p <端口>
```

### 查看房间信息

```bash
ming-drlms room info -r <房间名> -u <用户名> -H <主机> -p <端口>
```

### 查看成员

```bash
ming-drlms room members -r <房间名> -u <用户名> -H <主机> -p <端口>
```

### 房间策略

| 策略 | 说明 |
|------|------|
| `retain` | 保留消息历史 |
| `delegate` | 委托给其他服务器 |
| `teardown` | 最后成员离开时销毁 |

## 服务器配置

### 配置文件（C 服务器）

服务器启动参数可通过命令行或环境变量配置：

| 环境变量 | 说明 |
|----------|------|
| `DRLMS_PORT` | 监听端口 |
| `DRLMS_MAX_CONN` | 最大连接数 |
| `DRLMS_AUTH_STRICT` | 严格认证模式 |
| `DRLMS_JWT_SECRET` | JWT 密钥 |

### 安全配置

<Tabs>
  <Tab title="Linux/WSL">
    ```bash
    # 生产环境必须更换 JWT 密钥
    export DRLMS_JWT_SECRET=$(openssl rand -hex 32)
    
    # 启用严格认证
    export DRLMS_AUTH_STRICT=1
    ```
  </Tab>
  <Tab title="Windows">
    ```powershell
    # 生产环境必须更换 JWT 密钥
    $env:DRLMS_JWT_SECRET = -join ((48..57) + (97..102) | Get-Random -Count 64 | ForEach-Object {[char]$_})
    
    # 启用严格认证
    $env:DRLMS_AUTH_STRICT = "1"
    ```
  </Tab>
</Tabs>

## IPC 通信

### 共享内存模式

MP2 模式支持通过 IPC 进行进程间通信：

```bash
# 发送消息
ming-drlms ipc send --text "消息内容"

# 监听消息（tail 模式）
ming-drlms ipc tail --max 10
```

### IPC 配置

<Tabs>
  <Tab title="Linux/WSL">
    ```bash
    export DRLMS_SHM_KEY=0x4c4f4755
    ```
  </Tab>
  <Tab title="Windows">
    ```powershell
    $env:DRLMS_SHM_KEY = "0x4c4f4755"
    ```
  </Tab>
</Tabs>

<Note>
`DRLMS_SHM_KEY` 使用十六进制格式（如 `0x4c4f4755`）。
</Note>

## 故障排查

### 连接失败

<Tabs>
  <Tab title="Linux/WSL">
    ```bash
    # 检查服务器是否运行
    ming-drlms server status
    
    # 检查端口
    netstat -an | grep 15035  # server up 默认端口
    ```
  </Tab>
  <Tab title="Windows">
    ```powershell
    # 检查服务器是否运行
    ming-drlms server status
    
    # 检查端口
    netstat -an | findstr 15035
    ```
  </Tab>
</Tabs>

### 认证失败

1. 确认用户名密码正确
2. 检查 users.txt 文件格式
3. 检查 JWT_SECRET 配置

### E2EE 会话建立失败

```bash
# 重新生成密钥
ming-drlms e2ee generate-keys -u <用户名> --force

# 获取目标用户的密钥包
ming-drlms e2ee prekey-bundle -u <用户名> --target-user <目标用户>
```
