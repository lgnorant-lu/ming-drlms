## 概述

DRLMS 的 IPC 模块支持通过**共享内存**进行本地进程间文件传输。
此功能特别适用于**操作系统课程实验五**（共享内存进程通信）。

**核心特性**:
- ✅ 文件元信息传输（文件名、大小、修改时间等）
- ✅ 文件内容传输（自动分片）
- ✅ 信号量同步互斥（防止覆盖、重复）
- ✅ 完整性验证（大小校验）
- ✅ 进度显示

## 命令参考

### 发送文件

```bash
ming-drlms ipc file-send <FILE> [OPTIONS]
```

**参数**:
- `FILE`: 要发送的文件路径

**选项**:
- `--key`, `-k`: 共享内存键值（十六进制，默认: 0x1234）

**示例**:
```bash
# 发送文本文件
ming-drlms ipc file-send report.txt

# 发送二进制文件（PDF）
ming-drlms ipc file-send document.pdf

# 使用自定义键值
ming-drlms ipc file-send data.bin --key 0x5678
```

---

### 接收文件

```bash
ming-drlms ipc file-receive [OPTIONS]
```

**选项**:
- `--output`, `-o`: 输出目录（默认: ./received/）
- `--key`, `-k`: 共享内存键值（十六进制，默认: 0x1234）

**示例**:
```bash
# 接收到默认目录
ming-drlms ipc file-receive

# 指定输出目录
ming-drlms ipc file-receive --output ./downloads/

# 使用自定义键值
ming-drlms ipc file-receive --key 0x5678 --output ./tmp/
```

## 工作原理

### 传输流程

```
发送方                共享内存              接收方
  │                     │                    │
  │─── 1. FileMetadata ──→                   │
  │                     │  ←─── 读取元信息 ───│
  │                     │                    │ (解析文件名/大小)
  │                     │                    │
  │─── 2. 文件内容 ────→                      │
  │                     │  ←─── 读取内容 ─────│
  │     (分片传输)      │                    │ (保存到文件)
```

### 元信息结构

```c
typedef struct {
    uint32_t magic;          // 魔数验证 0x4D455441
    char filename[256];      // 文件名
    uint64_t filesize;       // 文件大小（字节）
    char checksum[65];       // 校验和（预留）
    time_t modified_time;    // 修改时间
    uint8_t transfer_mode;   // 传输模式（0=二进制）
    char sender[64];         // 发送者标识（PID）
    uint32_t sequence;       // 序列号
} FileMetadata;  // 总计 512 字节
```

### 同步机制

**信号量保护**:
- `sem_empty`: 空槽位数量（初始=2）
- `sem_full`: 满槽位数量（初始=0）

**防止覆盖**:
```c
// 写入前检查空槽位
sem_wait(sem_empty);  // 如果满，阻塞
write_data();
sem_post(sem_full);   // 通知读进程
```

**防止重复**:
```c
// 通过 msg_id 区分消息边界
if (hdr.msg_id != current_msg_id) {
    return;  // 新消息，返回当前消息
}
```

## 实验要求对照

### 实验五原始要求

| 要求 | 实现 | 验证 |
|------|------|------|
| 共享内存传输 | ✅ | `shm_write()` / `shm_read()` |
| 元信息传输 | ✅ | FileMetadata 结构 |
| 内容传输 | ✅ | 自动分片 |
| 信号量同步 | ✅ | sem_empty / sem_full |
| Spinlock 互斥 | ✅ | atomic lock |
| 防止覆盖 | ✅ | 信号量阻塞 |
| 防止重复 | ✅ | msg_id 机制 |
| 任意长度 | ✅ | 自动分片 (4080字节/片) |

### 元信息包含字段

- ✅ 文件名 (`filename`)
- ✅ 文件大小 (`filesize`)
- ✅ 修改时间 (`modified_time`)
- ✅ 发送者 (`sender`)
- ✅ 序列号 (`sequence`)
- ✅ 魔数验证 (`magic`)
- ✅ 传输模式 (`transfer_mode`)

## 高级用法

### 多文件传输

```bash
# Terminal 1: 接收
ming-drlms ipc file-receive --output ./batch/

# Terminal 2: 批量发送
for file in *.txt; do
    ming-drlms ipc file-send "$file"
    sleep 1  # 间隔1秒
done
```

### 大文件传输

```bash
# 发送 100MB 文件
ming-drlms ipc file-send large_file.bin

# 自动分片：100MB / 4080 ≈ 25,000 片
# 进度显示：
#   进度: 52428800 / 104857600 字节 (50.0%)
```

### 使用自定义键值（多对传输）

```bash
# 传输对 1: key=0x1111
ming-drlms ipc file-receive --key 0x1111 --output ./pair1/ &
ming-drlms ipc file-send file1.txt --key 0x1111

# 传输对 2: key=0x2222
ming-drlms ipc file-receive --key 0x2222 --output ./pair2/ &
ming-drlms ipc file-send file2.txt --key 0x2222
```

## 故障排查

### 问题：接收端显示 "魔数不匹配"

**原因**: 发送方使用旧版工具（无元信息）

**解决**:
```bash
# 重新编译
cmake --build build_win --target ipc_sender file_receiver
```

---

### 问题：文件大小不匹配

**原因**: 传输中断或共享内存键值不匹配

**验证**:
```bash
# 检查键值一致性
echo $DRLMS_SHM_KEY  # 或在 Windows: echo %DRLMS_SHM_KEY%

# 两端使用相同键值
ming-drlms ipc file-send test.txt --key 0xABCD
ming-drlms ipc file-receive --key 0xABCD
```

---

### 问题：找不到工具

**错误**:
```
Error: 找不到工具: file_receiver
```

**解决**:
```bash
# 1. 检查编译
ls build_win/src/tools/file_receiver.exe     # Windows
ls build_linux/src/tools/file_receiver       # Linux

# 2. 重新编译
cmake --build build_win --target file_receiver
```

## 与其他 IPC 命令对比

| 命令 | 用途 | 元信息 | 适用场景 |
|------|------|--------|----------|
| `ipc send` | 发送消息/文件 | ❌ | 一般数据传输 |
| `ipc file-send` | 发送文件+元信息 | ✅ | 实验五、生产环境 |
| `ipc listen` | 接收原始数据 | ❌ | 调试、日志流 |
| `ipc file-receive` | 接收文件+解析 | ✅ | 实验五、文件同步 |
